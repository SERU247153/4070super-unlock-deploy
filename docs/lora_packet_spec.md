# LoRa 패킷 명세 초안 — ML 관점 요구사항 (통신 설계는 정보통신 전공 영역)

## 1. 트래픽 특성 (ML 요구사항 요약)
- 업링크 주류: **이벤트 통지** (입고/사용/이상반출/정리) — 수십 바이트, 저빈도(분~시간 단위)
- 하트비트: 노드 상태(배터리/카운트 요약) — 시간당 1회 권장
- 다운링크: **대표벡터 등록/갱신** — 384B × 클래스수 (예: 3클래스 = 1152B)
  → LoRa 프레임(최대 255B) 기준 5~6프래그먼트 분할, 순번 부여

## 2. 업링크 패킷 포맷 (제안, 12B 고정)
```
[type:1B][node_id:2B][seq:2B][class:1B][delta:int8][conf:uint8][reserved:2B][crc:1B]
```
- type: 1=입고 2=사용 3=이상반출 4=정리묶음 5=하트비트
- conf: 0~255 (Conformal p-value 기반 신뢰도, 0=미사용)
- delta: ±개수 변화 (int8, ±127 초과 시 다중 패킷)

## 3. 재전송/신뢰성 요구
- 이벤트 패킷: ACK 수신까지 재전송 (중복 수신은 seq로 서버에서 제거)
- 하트비트/벡터갱신: ACK 선택 (손실 허용 — 다음 라운드에 재전송)
- 국내 규정 준수: 920MHz, 14dBm 이하, 송신 전 채널 확인(LBT)

## 4. 연합학습 트래픽 예산 (시뮬레이션 근거)
- 대표벡터 교환: 라운드당 노드 1536B×C (3클래스=4.6KB) — FedAvg(가중치 4.8MB) 대비 ~1,000배 절감
- 주기: 일 1회~주 1회로 충분 (프로토타입은 천천히 변함)

## 5. 보안
- node_id 인증(사전 공유키), 패킷 CRC, 필요 시 경량 AEAD
