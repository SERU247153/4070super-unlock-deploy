## 설치 과정에서 발견·해결된 이슈 2건

1. **rpm 4.16 매크로 제한** — `%global nv` 거부 → `%nvv` 자동 치환 패치 (02 스크립트 1.5절)
2. **RHEL 9.8 aperture 백포트** — 6.0 API가 5.14에 백포트됨 → `RHEL_RELEASE_CODE` 분기 보강 패치 (02 스크립트 1.6절)
3. (부수) /boot 공간 부족 — installonly_limit=2 로 커널 정리

## 1차 언록 시도 → 실패 (논콜드 카드)

- 셀렉터 기록(SS0=0x88888888, SS1=0x8)까지는 성공
- FLR 후 GSP 재기동 대기에서 `-110 ETIMEDOUT` (gpu-unlock 이슈 #23과 동일 패턴)
- 결과: nvidia 드라이버 통신 불가 → jupyter/ollama GPU 워크로드 중단

## 복구 (검증된 절차, 원격 5분)

```
grubby --update-kernel=ALL --remove-args="gpu_unlock.targets=all" → systemctl reboot
```

- 웜 재부팅만으로 GPU 완전 복구 확인 (nvidia-smi 정상, 도커 컨테이너 자동 복귀, Ollama 정상)

## 현재 상태

- 서버: 정상 운영 (잠긴 상태, ~70 TFLOPS)
- 부트 옵션: 재등록 완료 (`gpu_unlock.targets=all`)
- **대기**: 물리적 전원 차단(30초+) 후 재부팅 → 콜드 카드 언록 재시도 예정

## 2차 시도 (콜드 파워 사이클 후) → ✅ 성공

전원 완전 차단 30초+ 후 재부팅에서 `gpu_unlock: unlocked` 확인 (`stage=handoff ret=0 cleanup=0`).

## 운영상 주의 (남은 위험)

- **웜 재부팅은 피할 것** — 전원을 끊지 않는 재부팅에서는 언록 모듈이 재실행되며 논콜드 카드 조건으로 `-110` 실패가 재현될 수 있음
- 커널 업데이트 등으로 재부팅이 필요하면: 부트 옵션 제거 → 웜 재부팅 → 업데이트 → 콜드 파워 사이클로 재적용 권장
- 복구는 항상 가능: 부트 옵션 제거 → 재부팅 (원격 5분)

## 캘리브레이션: 전력·클럭·성능 특성

### 전력 스윕 (자연 부스트, 안정화 후 측정)

| 전력 제한 | 실측 클럭 | BF16 | FP16 |
|---|---|---|---|
| 160W | 2415 MHz | 83.7 TFLOPS | 72.7 TFLOPS |
| **180W** | 2760 MHz | **131.5 TFLOPS** | 118.7 TFLOPS |
| 200W | ~2400 MHz | 130.3 TFLOPS | 96.5 TFLOPS |
| 220W | 2685 MHz | 121.5 TFLOPS | 111.9 TFLOPS |
| 245W | 2378 MHz | 131.2 TFLOPS | 121.9 TFLOPS |

- ⭐ **180W가 성능/전력 스위트 스팟** — 245W와 동급 처리량(131.5 vs 131.2)을 전력 캡 180W로 달성
- 160W에서만 실질적 하락(83.7) — 언록 풀속 유지 최소 전력 ≈ 180W
- 24/7 상시 학습 워크로드는 180W 캡 권장 (전기료/발열 절감, 성능 손실 없음)

## 교훈

- Ada(40세대) 언록은 **반드시 완전 콜드 파워 사이클** 이후 시도할 것
