2. 시스템 아키텍처 (역할 분담)
--------------------------------------------------------------------------------
  데스크톱(4070S) = 두뇌 : 학습·등록·재학습·평가·연합병합·해석분석
  Edge Node       = 눈   : YOLO(어디/몇개) + DINOv2(무엇) + Conformal(확신)
                          3회 연속 확정, 사람 가림 시 보류, 어텐션 근거 로그
  LoRa 보드       = 입   : 결과 패킷(UART) → 920MHz → 게이트웨이 → MQTT
  서버(OpenStack) = 기억 : 수집·DB·대시보드·VPN
  * 통신 계층 설계(PCB/링크/프로토콜)는 정보통신 전공 7년의 전문 영역으로 위임

3. 데스크톱(4070S) 담당 업무 6종 — 전 자원 매핑
--------------------------------------------------------------------------------
  (1) YOLOv8 학습/재학습
      - COCO 전이학습 + 증강(mosaic/mixup/copy-paste/조명·각도) [edge_yolo_config.yaml]
      - BF16 autocast + TF32(high) + AdamW(fused) + EMA + 코사인LR + 조기종료
      - 헷갈린 장면 자동 수집 → 재학습 → 성능 개선 시에만 배포(게이팅)
  (2) DINOv2 학습/등록
      - 기본: 선형 프로브 (2026 문헌: 미세조정 능가)
      - 유사 자재: QLoRA 4비트 + 그라디언트 체크포인팅 [dinov2_classifier.py]
      - 새 자재 등록: 사진 5~10장 → 어텐션 가중 풀링 임베딩 → 평균 → 대표벡터
      - FP8(Transformer Engine): 배치 임베딩 대량 생성 시 추가 가속 여지
  (3) Conformal 교정
      - 교정셋으로 q 산출 → 엣지 "모르면 보류"의 수학적 근거 [conformal.py]
  (4) 해석·진단
      - 어텐션 rollout 맵 + HiResCAM → 판정 근거 Figure, 오판 원인 분석
        [attention_map.py]
  (5) 연합학습 병합 서버 (LoRa 페더레이티드 러닝 — 독창 기여)
      - 각 적치장 노드: 로컬 대표벡터 갱신분(수백 바이트)만 LoRa로 상향
      - 데스크톱: 가중 평균 병합 + 정상성 검사(리셋 가드) 후 하향 배포
  (6) 평가/실험
      - 개수 정확도, 자재/사람 검출, 등록 장수별(1/3/5/10) 식별 정확도
      - 데스크톱 vs 보드 동일 시험셋, 기록 전달률·지연, 어텐션 근거 정성평가

4. 파이프라인 전 단계 × 적용 기법 (성능 설계 확정)
--------------------------------------------------------------------------------
  [데이터]    HF/데이터셋 캐시 → /workspace 영속 볼륨, 증강 파이프라인
  [학습]      TF32(high)+BF16, torch.compile, fused AdamW, EMA, 체크포인팅,
              QLoRA(선택), 언록 132TFLOPS, 전력 180W
  [등록]      어텐션 가중 임베딩 + L2 정규화 + 코사인 유사도 + Conformal q
  [엣지]      TensorRT FP16/INT8(Nano), NCNN(RPi5), CUDA Graph, 프레임 스킵,
              ROI 크롭, 루프 ≤50ms(참조 5.3ms)
  [통신]      결과만 전송(수십 바이트), 중요 기록 재전송, 채널 확인(국내 기준)
  [서버]      MQTT→DB→Grafana, VPN(L2TP/IPsec)

5. 성능 목표치
--------------------------------------------------------------------------------
  데스크톱: BF16 GEMM 132TFLOPS 유지, 임베딩 <1ms(CUDA Graph),
            YOLO 학습 에포크 <수분(소량 데이터 기준)
  엣지:     판정 루프 ≤50ms, 3회 연속 확정 지연 ≤1s(스킵 포함)
  통신:     패킷 <64B, 920MHz/14dBm 이하, 전달률 ≥99%(재전송 포함)
  정확도:   자재 검출 mAP50 ≥0.85(모의 적치장), 식별 ≥0.90(10장 등록)

6. 연구 기여 (차별화 5축) — 선행연구 대비 포지셔닝
--------------------------------------------------------------------------------
  A. 입고·사용·반출 이벤트 자동 기록
     - 기존 건설 계수 연구[1][2]는 '개수'만 산출 — 이벤트 기록은 본 연구 고유
  B. 대표벡터 교환형 초경량 연합학습 (LoRa)
     - LoRa 기반 FL은 2024-2026 활발[21][22][23][24][25][26] — 단, 모두
       모델 가중치(수 KB~수백 KB) 교환. 본 연구는 **대표벡터(수백 바이트)만
       교환** → 패킷/공중시간 10배 이상 절감 + 도메인(건설 자재) 최초
  C. Conformal 기반 불확실성 정식화[18] + 3회 연속 확정
     - "모르면 보류"를 보장된 오류율로 정식화 — 휴리스틱 임계값과 차별
  D. 어텐션 기반 해석가능 판정[16][17] (rollout+키정규화 / HiResCAM / 가중 풀링)
  E. 실시간 예산 정식화 (ms 단위 측정·보고, CUDA Graph[PyTorch 문서])
     - 텐서코어 언록 기반[27][28] — 데스크톱 참조 189FPS

7. 추진 단계
--------------------------------------------------------------------------------
  1단계(현재) : 환경·기법 선설정 완료, 데이터 대기
  2단계       : 자재 사진 수집(2~3종×50~300장) → YOLO 학습 → 평가
  3단계       : DINOv2 프로브/QLoRA 학습 → 등록 실험(1/3/5/10장) → Conformal 교정
  4단계       : 엣지 변환(TensorRT/NCNN) → 보드 실측(ms/FPS) → LoRa 연동
  5단계       : 연합학습 프로토콜 설계 → 시뮬레이션 → 현장 시험(2~4주)
  6단계       : 논문 작성(측정 데이터 + 어텐션 Figure + 링크버짓)
